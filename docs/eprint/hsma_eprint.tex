\begin{abstract}
We present HSMA, a Layer-1 protocol architecture that eliminates Maximum
Extractable Value (MEV) at the cryptographic layer and achieves succinct
recursive state folding with an $O(1)$-size accumulator, with all
cryptographic components implemented and verified by a bilingual
golden-oracle methodology.

Our first contribution is a \emph{threshold-encrypted mempool} in which
decryption shares are bound to the committed transaction ordering root:
no committee member can learn payload contents before the execution
position is irreversibly committed, and no party can alter the sequence
after learning contents. We prove that pre-freeze threshold-scale
decryption is structurally impossible by counting: adversary identities
are capped at $100 < t = 112$, yielding $\varepsilon = 0$ (not merely
improbable).

Our second contribution is a \emph{Non-Uniform IVC (NIVC) fold
accumulator} of exactly 41 bytes (digest $+$ count $+$ program counter),
constant regardless of the number of folded state transitions. We prove
that the NIFS fold preserves satisfaction exactly (the identity is
polynomial in the challenge $r$), and we present the complete
Phase-0 pipeline: fold semantics, CCS constraint layer, accumulator,
sum-check engine, commitment layer, and light-client epoch-header
certificate, all golden-proven against a Python oracle bit-exact on both
sides of the language boundary.

Our third contribution is methodological: an \emph{append-only decision
ledger} paired with \emph{bilingual golden-oracle proving} (Python computes,
C++ verifies, the goldens arbitrate). Over 25 conformance steps, this
methodology caught 114 defects --- including a publicly-derivable KEM key
--- each with a named fix, while maintaining zero silent regressions
across 223 design decisions.

\end{abstract}

\section{Introduction}

\subsection{The MEV Problem}

Maximum Extractable Value (MEV) arises when privileged network
participants (sequencers, validators) can observe, reorder, insert, or
censor transactions before they are finalized. On existing Layer-1
platforms, this takes the form of front-running, sandwich attacks, and
positional insertion --- all of which extract value from users without
providing any service.

Existing mitigations fall into three categories, each with limitations:

\begin{enumerate}
\item \textbf{Commit-reveal schemes:} Require two interaction rounds,
  increasing latency and enabling griefing.
\item \textbf{Threshold encryption (Shutter, Ferveo):} Decryption shares
  are not bound to the ordering --- a committee member can decrypt early
  and the evidence is retroactive punishment, not structural prevention.
\item \textbf{TEE-based ordering (SUAVE):} Trusts hardware enclaves
  rather than cryptographic guarantees.
\end{enumerate}

\subsection{Our Approach: Order-Bound Decryption}

HSMA inverts the pipeline: transactions are encrypted, the ordering is
committed, and \emph{only then} are decryption shares constructible.
The binding is structural: each share's preimage includes the committed
\texttt{order\_root}, so a share for a pre-freeze ordering cannot be
formed. Combined with the identity cap ($m_{\text{adv}} \le 100 <
t = 112$), pre-freeze threshold-scale decryption is
\textbf{impossible}, not punishable.

\subsection{Recursive State Folding}

Blockchain state grows linearly with transaction count, degrading
light-client verification. HSMA addresses this with a Non-Uniform IVC
(NIVC) architecture over the Pallas/Vesta 2-cycle: each epoch's state
transition is folded into a constant-size accumulator (41 bytes), and
the accumulator chains across epochs via \texttt{prev\_digest}
absorption. The fold's correctness is preserved exactly: the NIFS
identity is polynomial in the challenge, so the folded instance
satisfies the constraint system with the same soundness as the
originals.

\subsection{The Methodology Contribution}

A significant barrier to trust in Layer-1 implementations is the gap
between specification and code. HSMA addresses this with a methodology
 comprising three elements:

\begin{enumerate}
\item \textbf{Append-only decision ledger:} Every design decision
  receives a unique identifier (DEC-001 through DEC-223), and
  supersession chains are explicit. No decision is silently reversed.
\item \textbf{Bilingual golden-oracle proving:} For each module, a
  Python oracle computes the expected outputs, and the C++
  implementation must reproduce them bit-for-bit. The goldens arbitrate:
  when the two languages disagree, the defect is localized to the
  exact limb.
\item \textbf{Adversarial self-review:} Each development step concludes
  with a review pass that attempts to find defects in the step's own
  output before the gate runs. Over the project's lifetime, this
  caught 114 defects --- each logged, named, and fixed.
\end{enumerate}

\section{Preliminaries}

\subsection{The Pallas/Vesta 2-Cycle}

We work over the Pasta cycle: Pallas ($y^2 = x^3 + 5$ over
 $\mathbb{F}_p$) and Vesta ($y^2 = x^3 + 5$ over $\mathbb{F}_q$),
where $\#\textsf{Pallas}(\mathbb{F}_p) = q$ and
 $\#\textsf{Vesta}(\mathbb{F}_q) = p$, with $p$ and $q$ both
 $\approx 2^{254}$. This cycle natively supports IVC folding without
foreign-field arithmetic.

\subsection{BLS12-377 Threshold Signatures}

Threshold signatures, the randomness beacon, and epoch certificates
operate on BLS12-377: base field $q_{\text{BLS}} \approx 2^{377}$,
group order $r \approx 2^{253}$. Since $r < 2^{253} < 2^{254} \le p$,
every scalar embeds losslessly into one Pallas limb.

\subsection{Poseidon-3 Hash}

All SNARK-friendly hashing uses Poseidon-$3$ ($t = 3$, $\alpha = 5$,
 $R_F = 8$, $R_P = 56$) with domain-separated initialization vectors
per usage context. The MDS matrix is Cauchy with machine-checked
non-singularity of all minors. Round constants derive via SHA-256
counter DRBG with rejection sampling.

\section{Order-Bound Decryption (The Zero-MEV Core)}

\subsection{The Commit-then-Simulate Pipeline}

\begin{enumerate}
\item \textbf{Intake:} Encrypted envelopes
  $\{pk, \text{nonce}, \text{escrow}, ct\}$ are gossiped.
\item \textbf{Ordering Lock:}
  $\text{order} = \text{Sort}(H(\texttt{HSM\_ORDER\_v1} \| \text{beacon}_E \| H(ct)))$;
  the committee signs $\text{order\_root}$.
\item \textbf{Share Release:} Each member $j$ publishes
  $D_j = [S_j]R \in G_2$ (the partial decryption), bound to the preimage
  $\texttt{HSM\_DEC\_SHARE\_v2} \| \text{epoch} \| \text{order\_root} \|
  H(ct) \| \mathrm{ser}(D_j)$.
\item \textbf{Verification:} The pairing identity
  $e(G_{1,\mathrm{gen}}, D_j) = e(Y_{1,j}, R)$ verifies each share
  against the Feldman public key.
\item \textbf{Aggregation:} Anyone computes
  $D = \sum_j \lambda_j D_j = [S]R$ (the Lagrange reconstruction) and
  re-derives the key $k = \mathrm{KDF}([S]R)$ to decrypt.
\end{enumerate}

\begin{definition}[Order-Before-Knowledge]
No party can learn payload contents before the execution position is
irreversibly committed. Enforcement: the share record cannot exist
before $\text{order\_root}$ exists (it is in the preimage), and
threshold-scale decryption requires $t$ shares, which requires $t$ distinct identities, which requires $t \le m_{\text{adv}} \le 100 <
112$ --- impossible by counting.
\end{definition}

\begin{theorem}[Structural Zero]
Under the identity cap $m_{\text{adv}} \le 100 < t = 112$: the
probability that $t$ adversarial decryption shares for a pre-freeze
ordering exist is $\varepsilon = 0$.
\end{theorem}
\begin{proof}
The adversary controls at most $m_{\text{adv}} \le 100$ identities
(by the $w_{\text{floor}}$ cap, DEC-039). Constructing a valid
decryption share requires signing under a valid committee key share
 $S_j$, which requires holding identity $j$'s key. Since $m_{\text{adv}} < t$,
the adversary cannot accumulate $t$ valid shares regardless of
computation. $\varepsilon = 0$ identically.
\end{proof}

\subsection{Implementation Verification}

The complete pipeline is implemented in both Python (the oracle) and
C++20 (the production language), verified bit-exact: 516 golden
test-vectors for the field arithmetic, 31/31 conformance tests for
the protocol, and 3 negative cases (malformed share, wrong
 $\text{order\_root}$, tampered ciphertext) each rejected at the
correct verification seam. The $k_2 = k$ end-to-end assert (the
committee's re-derived key equals the sender's key) is the machine
check that the KEM is not publicly derivable --- a defect
(CA-R61) that the oracle caught before any golden shipped.

\section{The NIVC Fold Accumulator}

\subsection{The Step Family}

The state transition is decomposed into three circuit types:
 $F_{\text{head}}$ (absorbs the previous digest and the decree root),
 $F_{\text{exec}}$ (processes each decree entry through the constraint
gates: binding, nonce, LT gate, self-send routing, padding-neutrality),
and $F_{\text{close}}$ (absorbs the entry count). The program counter
enforces the transition matrix
 $\{\text{head} \to \text{exec}^+, \text{exec} \to \text{close}\}$;
all other edges are unsatisfiable (SAT-proof, whitepaper item 7).

\subsection{The 41-Byte Accumulator}

The NIVC accumulator is:
\[
\mathcal{A} = \{\text{digest} \in \mathbb{F}_p^{(32\text{B})},
\text{count} \in \mathbb{Z}_{2^{64}}^{(8\text{B})},
\text{pc} \in \{0,1,2\}^{(1\text{B})}\}
\]
Total: 41 bytes, \textbf{constant regardless of the number of folded
entries}. This is the succinctness mechanism: $\pi_E$'s representation
is $O(1)$ in the number of folded entries.

\begin{theorem}[Satisfaction Preservation]
The NIFS fold of two satisfying instances produces a satisfying
instance: if $Az_1 \odot Bz_1 = u_1 \cdot Cz_1$ and
 $Az_2 \odot Bz_2 = u_2 \cdot Cz_2$, then the folded instance
 $(z_1 + r \cdot z_2, u_1 + r \cdot u_2, E_1 + r \cdot T + r^2 \cdot E_2)$ satisfies the constraint system, where
 $T = Az_1 \odot Bz_2 + Az_2 \odot Bz_1 - u_1 \cdot Cz_2 - u_2 \cdot Cz_1$.
\end{theorem}
\begin{proof}
The identity is polynomial in $r$. Substituting:
\[
A(z_1 + rz_2) \odot B(z_1 + rz_2) - (u_1 + ru_2) \cdot C(z_1 + rz_2)
= E_1 + rT + r^2E_2
\]
which holds for \textbf{any} $r$ by bilinearity of the component-wise
products. The NIFS challenge $r$ is derived via
 $r \gets P_3(\texttt{HSM\_FOLD\_v1}, \ldots)$, ensuring transcript
binding.
\end{proof}

\section{The Light-Client Certificate}

Light clients download the epoch header
 $(\text{height}, \text{state\_root}, \text{digest}_E,
\text{beacon}, \sigma_{\text{cert}})$ and verify with
\textbf{one pairing}:
 $e(\sigma, G_{2,\mathrm{gen}}) = e(H(\text{pre}), Y)$, where the
preimage binds the height, epoch, state root, fold-chain digest, and
beacon digest. The threshold-BLS certificate is produced by the same
G7 committee that testifies across all pillars. Chain continuity is
recomputed: $\text{digest}_E = P_3(\texttt{HSM\_FOLD\_v1},
\text{prev\_digest}, \text{decree\_root})$.

\section{The $\varepsilon$-Budget Composition}

\begin{theorem}[Composition]
The system soundness is:
\[
\varepsilon_{\text{sys}} = \underbrace{0}_{\text{quorum}}
+ \underbrace{0}_{\text{committee}}
+ \underbrace{0}_{\text{eclipse}}
+ \underbrace{2^{-128}}_{\text{PCS}}
+ \underbrace{2^{-127}}_{\text{field}}
+ \underbrace{2^{-171}}_{\text{hash}}
+ \underbrace{2^{-110}}_{\text{BLS}}
\approx 2^{-110} \text{ per epoch}
\]
\end{theorem}

The zeros are \emph{engineered}: L1 by authentication + frozen
snapshots + $\varphi_{\text{floor}} > f/\alpha$; L2 by the identity
cap $m_{\text{adv}} \le 100 < t$; L4 by INV-G3 containment. Remove
the structural floor and the sortition degrades to $2^{-73}$ ---
below the $2^{-80}$ target. The zeros are a parameter mandate.

\section{Conclusion}

HSMA demonstrates that a Layer-1 protocol can achieve structural zero
MEV (impossible, not punishable), O(1) state-folding verification (a
41-byte accumulator), and a light-client verification path (one
pairing per epoch header) --- with every cryptographic component
implemented, golden-proven across a language boundary, and maintained
under an append-only decision discipline that makes the engineering
process itself auditable.

The remaining work is the production proof system (homomorphic PCS and
HyperNova multifold for commitment folding) and the network layer. The
Phase-0 foundation is complete and golden-proven.
